# 原生横屏广告：无障碍复查与 OCR 成本

此报告记录此前 0.2.0 的复查阶段。后续已采到真实原生横屏倒计时并完成 0.2.1 的一次试滑与 OCR 回退，见[后续验收](../hongguo-landscape-badge/TEST.md)；下文保留当时的样本和测量结果。

2026-10-11；Android 14 ARM64 模拟器，2340 × 1080 横屏，红果 7.3.9.32。ADSkip 自动跳过、横屏辅助识别全程关闭；通过已授权的 ADB 手动切集、跳过已确认有继续观看提示的广告。研究探针只读取和截图，不自动上滑。

实测不支持“只因为广告已结束或暂停，才读不到提示”的解释。收集到 5 种广告素材，在视频画面变化、刚切入广告、手动暂停的阶段，右上方肉眼可见“上滑继续观看剧集”，无障碍仍没有对应文字。可读的“广告”标记和部分商品内容则正常返回。由此推断，当前版本的这组布局没有向无障碍提供跳过提示语义；尚不能确定其内部绘制实现，也不能推广到所有广告、设备或版本。

## 无障碍尝试及稳定特征

研究模式读取所有层级，包括没有文字、资源 ID 和 `importantForAccessibility=false` 的节点；扩展读取 hint、stateDescription、tooltip、子节点数量、动作列表，并监听全部事件类型。第二种素材起禁用无障碍缓存；Swisse、小欧、FIRS 还通过文字（上滑、继续、秒、跳过）和历史资源 ID（aq8、ar1、k8、jjy）直接查询节点。都没有补出可跳过提示。早期事件遍历了源节点子树，后期仅记录事件源，避免诊断负载过大。

五种素材在完整研究节点中都有同一个提示空容器：

| 属性 | 当前设备实测值 |
| --- | --- |
| class | android.view.ViewGroup |
| bounds | [1534, 67, 1969, 155] |
| text / contentDescription / resource ID | 空 / 空 / 无 |
| hint / stateDescription / tooltip | 无 |
| children | 0 |
| visible / enabled / selected / clickable / important | true / true / false / false / false |
| actions | 76 |
| 相邻“广告”节点 | contentDescription=广告；bounds=[2036, 92, 2114, 131]；important=true |

`ad02-fresh/ad-00s.json` 是研究命令生效前的一帧，仅有 50 个筛选节点；后续 96 个完整研究样本均含上述空容器。普通播放器的下一集按钮 `ar1`、标题 `k8` 可正常读取；在切换动画中，遍历与定向查询可能短暂返回不同坐标，说明诊断需注意时效，但广告提示即使强制新读取仍无文字。

这些结构能帮助定位提示区域，不能证明其文字是“继续观看”还是“几秒后可继续”。本轮没有捕获原生横屏真实倒计时，因而没有把空容器或单独“广告”标记加入自动上滑规则。直播入口文案属于这些广告素材的一部分，不构成剧集间直播卡片的验收。

包含非重要节点的标志和禁用缓存 API 说明见 [Android 服务标志文档](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo#FLAG_INCLUDE_NOT_IMPORTANT_VIEWS)、[Android setCacheEnabled 文档](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService#setCacheEnabled(boolean))。研究探针的高频读取、定向查询、事件采集只用于本次排查，没有加入产品检测循环。

## OCR 性能与识别比较

共 14 张图片：本轮五种素材各两帧、男装手动暂停一帧、此前 Swisse 暂停一帧、两张普通剧集负例。每张读取 3 次，共 42 次，其中第 1 次初始化，余下 41 次为热运行。直接使用产品的 `HeaderOcr` / `VisualRules`，同一裁剪、白色文字过滤、完整文案、最低置信度 80；没有降低阈值或模糊修正文案。

计时包含模型初始化（首轮）、像素过滤、放大、OCR 和规则校验，**不包含截图获取、PNG 解码、无障碍读取、两次确认等待和手势**。在关闭两个无障碍服务后运行独立验收助手，背景红果仍播放。这些是模拟器结果，没有测量真机帧率、电量或完整端到端跳过延迟。

| 相同完整样本、清空验收助手模型后的运行 | 产品 tessdata_best | 试验 tessdata_fast |
| --- | ---: | ---: |
| 首次初始化及读取 | 318 ms | 231 ms |
| 热运行中位数 | 120 ms | 91 ms |
| 热运行 95 分位 | 236 ms | 158 ms |
| 未匹配预期的读取次数 | 0 / 42 | 12 / 42 |
| 进程 PSS：开始 → OCR 存活时结束 | 5,579 → 68,594 KB | 5,587 → 64,524 KB |

现有模型重测结果为 118 ms 中位数、232 ms 95 分位，与上述接近。完整样本结束时进程内存增量约 61.5 MiB；更早的 10 张样本运行结束时约 92.6 MiB，说明内存结果受堆分配/回收影响，不能称为稳定峰值或纯模型内存。确实存在数十 MB 的成本。

轻量模型在 EYGRBA 和小欧的四张正例上均漏检，分别返回 `content` 或保守的 `ad-waiting`；正常剧集负例未触发。现有模型全部正例匹配，正常剧集没有匹配 `ad-ready`；带普通播放器数字的负例保守返回 `ad-waiting`，这不是真实广告倒计时验证。重复读取不能证明未来场景 100% 准确。

保留当前产品模型，不采用轻量模型。本轮未修改 0.2.0 APK 或产品识别阈值。轻量模型仅下载到开发缓存，SHA-256 为 `a5fcb6f0db1e1d6d8522f39db4e848f05984669172e584e8d76b6b3141e1f730`，来源为官方 tessdata_fast 仓库。

## 实现决定与收尾

继续使用无障碍文字作为首选；仅在红果原生横屏、可读“广告”标记、无法读取继续观看提示且用户单独开启辅助识别时执行 OCR。单工作线程、局部提示识别、连续确认和冷却不变；不会根据空节点的位置直接跳过。当前实现不保证瞬时反应：两次确认至少相隔 900 ms，另有采样和识别耗时。

新增 20 份真实节点回放，合计通过 59 份页面回放、25 项动作门控、22 项视觉规则检查；现有模型的 42 次样本读取和原有 3 张引擎回放通过。本轮对新素材进行了手动采样与离线识别，没有声称已逐个完成产品自动跳过。

采集工具为 [collect-landscape.py](../../tools/android-probe/collect-landscape.py)，研究模式默认关闭自动手势，最多手动切集 12 次并在布局无法确认时停止。收尾禁用研究探针，恢复 ADSkip 服务，自动跳过与横屏辅助识别均关闭，累计完成上滑仍为 4；见[最终设置截图](final-settings.png)。
