# ADSkip 0.2.2 初版

安装包：[`ADSkip-0.2.2.apk`](../dist/ADSkip-0.2.2.apk)，约 25 MB，可覆盖升级此前版本。原生横屏广告改为先根据无障碍“广告”标记试滑一次，未退出再使用单独开启的横屏辅助识别。最低 Android 8.0（API 26）；OCR 回退需要 Android 11（API 30）或以上。实测为 Android 14 ARM64 模拟器、红果 7.3.9.32，尚未验证真机或其他红果版本。

## 使用

1. 安装并打开 ADSkip，在系统设置开启“ADSkip 广告助手”。
2. 需要处理首次试滑未退出的横屏广告时，打开“横屏辅助识别”，阅读本机截图说明并确认。首次安装默认关闭。
3. 打开“自动跳过”，再打开红果。首次安装自动跳过默认关闭；覆盖升级保留配置、记录和计数。
4. 原生横屏、右上方精确“广告”标记连续两次命中且间隔至少 900 ms 后，先尝试上滑一次。不可读的倒计时此时可能尚未结束，红果可能拒绝退出。
5. 试滑完成后留出约 1.8 秒检查页面。广告标记消失且出现稳定的剧集播放器特征才确认返回；同一次广告不因标记短暂消失、文案变化、暂停或服务重连而重新盲试。
6. 广告仍在时，若辅助识别已开启，则在本机读取右上方提示。倒计时和无法确认的画面不授权第二次上滑；完整继续观看提示、置信度、连续确认、窗口一致性和时效均满足后再操作。辅助识别关闭或系统截图不可用时保持等待。
7. 每次被系统接受的手势后仍有 8 / 12 / 20 秒冷却；首次试滑和后续确认上滑都受此约束。关闭自动跳过停止检测，关闭辅助识别停止新的截图。通知栏“暂停”同样有效；已经交给系统的 350 ms 手势可能在关闭后完成。

只在红果前台、屏幕点亮且未锁定时工作。竖屏和旋转后的居中窄窗口仍走无障碍文字规则，已读到倒计时的页面不试滑。剧集之间的直播卡片继续 pending，识别到保守直播特征时不操作。广告素材里的“点击进入直播间”不等于已验证直播插入卡片。

## 实测与性能

0.2.1 曾实测两条可立即跳过的横屏广告和一条带 8 秒倒计时的广告：前两条第一次试滑即恢复剧集，未进入 OCR；第三条首次试滑失败，随后 OCR 等待倒计时结束，再次上滑并确认返回。此前还记录了刚切入的 7 秒倒计时在 ADB 单次试滑后仍停留于广告的反例。详见[0.2.1 验收](../artifacts/hongguo-landscape-badge/TEST.md)。

0.2.2 针对真机横屏倒计时后未跳过的反馈修复提示定位：优先读取非重要无障碍节点中空提示框的边界，框不存在时按右上方广告标签的位置和高度定位附近区域，替代固定窗口百分比裁剪。原有模型、预处理、置信度 80 和完整文案要求保留。新增每种原因每次广告最多一次的诊断日志，不保存识别文字。

用户压缩录屏顺序回放已能在倒计时结束后连续确认；部分模糊帧仍不能完整确认。提示容器边界是录屏像素标注，真机的实际无障碍树和最终手势效果尚未直接验证。模拟器实测一条 8 秒倒计时广告首次失败后回退识别、第二次上滑成功并返回剧集。原有 21 张截图的 63 次引擎回放通过，热读取中位约 50 ms、95 分位约 53 ms，不包含截图、界面读取、确认和手势。详见[本次修复报告](../artifacts/hongguo-device-countdown/REPORT.md)。

仍使用原有离线模型，首次加载有成本，截图及模型工作会增加内存。成功返回剧集、关闭辅助识别或暂停时释放识别器；常规首次试滑成功时不调用 OCR。尚未测量真机帧率、电量或稳定峰值内存。提示位置、颜色、文案变化或截图被禁止时，回退可能保持等待。本版不点击“跳过”按钮，也不自动领取优惠券或进入商品/直播页面。

此前横屏无障碍复查见[研究报告](../artifacts/hongguo-landscape-a11y/REPORT.md)，0.2.0 的首次 OCR 自动跳过见[历史验收](../artifacts/hongguo-landscape/TEST.md)。历史研究中的“尚未取得原生横屏倒计时”已由本轮新增样本补齐。

## 数据与权限

没有网络、录音或存储权限。无障碍服务声明读取界面、执行手势和截图能力；辅助识别需用户单独开启。截图只用于本机临时识别，不保存、不上传，识别文字也不保存。

保存开关、冷却、完成上滑计数、最近 100 条操作记录和一个“本次横屏广告已尝试”的布尔状态。该状态没有广告或账号内容，仅在确认返回剧集后清除，避免重连时重复试滑。另有内置模型及本地安装副本。计数表示系统回调完成的手势，**失败试滑也会计入，不能当作成功跳过广告的数量**。日志区分试滑完成、广告仍在、后续上滑和确认返回。清空记录不清零计数，卸载删除本地数据，备份关闭。

## 构建与测试

使用本机 SDK build-tools 36.0.0、android-34 和 Android Studio JDK。首次准备 OCR 依赖需要下载固定版本 AAR 并校验 SHA-256；模型和许可证包含在源码中，准备后可离线构建，无需 Gradle。

```sh
./app/prepare-ocr.sh
./app/tests/run.sh
./app/build.sh
./scripts/adb.sh install -r dist/ADSkip-0.2.2.apk
./scripts/adb.sh shell am start -n io.adpass.app/.MainActivity
```

可用 `ADPASS_ANDROID_SDK` / `ADPASS_JAVA_HOME` 覆盖路径。包名 `io.adpass.app`，versionCode 5，versionName 0.2.2，分发包不可调试。包含 arm64-v8a、armeabi-v7a、x86、x86_64 库，实际仅验证 ARM64。沿用 `.local/android/app-build/preview.keystore` 的预览签名，可覆盖升级；这是内部试用版，未发布商店。

通过 25 项门控、22 项视觉规则、22 项一次试滑与返回确认检查、66 份页面回放，以及 63 次实际引擎读取和原有三张截图的引擎回放。独立 OCR 验收助手与产品共用 `HeaderOcr` / `VisualRules`。`ADSKIP_TEST_BUILD=1 ./app/build.sh` 生成只用于本机读取验收状态的可调试版本，位于 `.local/android/app-build/test.apk`；正常构建仍生成不可调试的分发包。实际服务逻辑相同，验收后已换回分发包。项目截图属于开发采集，产品不保存截图。

离线识别使用 Tesseract4Android 4.9.0 和 tessdata_best 中文模型，许可证与来源见 [`assets/licenses/NOTICE.txt`](assets/licenses/NOTICE.txt)。This software is based in part on the work of the Independent JPEG Group.
